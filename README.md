# 医保政策捕获与 AI 解读平台

面向 **玉溪澄江市乡镇卫生院** 的官方医保政策定时抓取 + AI 解读站点。抓取源仅限三个政府官方站点，
形成「国家主线指导 → 云南省政策引导 → 玉溪市政策执行」三级对照。

## 三、架构

```
医保政策捕获网站/
├─ backend/
│  ├─ app/
│  │  ├─ config.py       # 源/栏目/定时/大模型配置
│  │  ├─ database.py     # SQLite 建表与设置
│  │  ├─ sources.py      # 三站点列表+详情解析器
│  │  ├─ analyzer.py    # 规则解读 + 大模型接口预留
│  │  ├─ crawler.py      # 政策抓取；run_all()=政策+曝光组合任务
│  │  ├─ exposure.py    # 案例/退出公告机构与字段抽取
│  │  ├─ exposure_crawler.py # 曝光台抓取调度与去重入库
│  │  ├─ scheduler.py     # APScheduler 每日/每周定时
│  │  └─ main.py        # FastAPI REST + 静态托管
│  ├─ data/policies.db   # SQLite（自动生成）
│  └─ crawl_once.py      # 命令行一次性抓取
├─ frontend/             # 静态页面（index/style/app）
└─ start.ps1 / start.bat # 一键启动
```

数据落库表：`policies`（政策）、`analysis`（解读）、`crawl_log`（抓取日志）、`exposures`（曝光台案例/退出机构），另有 `settings` 表存运行配置。

## 四、AI 解读

- **解读顺序（先解读后发布）**：列表抓取 → 新条目入库 → 抓正文 → 生成解读写入 `analysis` 表 → 前端展示；条目始终带解读，不会出现无解读空发布。
- **默认（本地规则解读，无需联网/密钥）**：主题标签、适用对象、生效日期、要点提炼、政策类型、效力状态、待遇/支付标准句、合规风险句，以及面向乡镇卫生院的相关度评分（0–100）与执行建议。
- **大模型解读（可选，OpenAI 兼容）**：默认预置**永久免费的智谱 GLM-4-Flash**（国内直连）：到 open.bigmodel.cn 手机号注册、控制台复制 API Key，在网页「抓取与AI设置」启用并填入 Key 即可，接口地址与模型已预置。也可改配豆包方舟 `https://ark.cn-beijing.volces.com/api/v3`（模型填接入点 ID ep-xxxxxx）等其他兼容接口；调用失败自动回退规则解读。
  大模型在摘要/要点/相关度之外，补充一期结构化维度：**政策类型**（管理办法/实施细则/规范性文件/政策解读/目录清单/公示公告）、**效力状态**（现行有效/试行中/征求意见/已废止/未知）、**核心要素**（发文主体/适用对象/适用条件/标准额度/办理时限/执行时间，键值卡）、**基层落地动作**清单、**合规风险红线**、**待遇/支付标准**条目；并按对标补齐**分层影响与影响矩阵**：整体影响分级（高/中/低/未涉及）、上位依据与政策层级衔接（国家→省→市）、对市级/经办层面的影响、固定 8 个基层业务维度（门诊统筹与慢病、住院与DRG/DIP结算、药品目录与集采配备、医保结算与系统操作、考核与违规风险、信息化与数据上报、人员与培训、其他影响）逐项判定分级与判断说明，未涉及维度显式标注“该维度未提及”；另提炼原文关键数据（比例/金额/日期/数量）。规则兜底按关键词粗判维度涉及与否与影响分级，上位依据按国家/省/市层级给衔接句。主题标签与适用对象自动归一到标准词典以匹配前端筛选；政策卡片用角标区分「大模型解读 / 规则解读」。`analyzer.llm_chat_json` 为通用 OpenAI 兼容 JSON 调用（JSON 模式失败自动降级重试），政策问答复用同一链路。历史条目需经批量重解读补全新维度，空分区前端自动隐藏。
- **解读质量约束与兜底**：提示词要求摘要含实质内容与原文数字、要点为完整句子、要素只填原文确有项、动作为基层具体动作；后端再做输出清洗——标准条目必须含数字与单位、风险必须含禁止/追回/处罚等硬措辞（剔除“不当/不规范/不到位”类泛化推测）、动作剔除“加强领导/提高认识”类口号、要素剔除“无/待定/根据实际”占位值、要点剔除过短标签词；摘要或要点过空时回退规则抽取。主题标签最多 5 个并对齐标准词典（词典外标签映射或剔除），适用对象最多 4 个；模型偶发返回对象字段会被归一为干净中文文本。大模型请求对超时/网络/5xx 退避重试一次；规则兜底同步收紧：标准句须含数字单位、效力状态不再因单处“废止”字样误判为已废止、摘要去除呼告前缀。
  环境变量：`LLM_ENABLED / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`。
- **为何不用本地模型**：本机 16G 内存 + GT730 亮机卡，无 CUDA 加速，本地 7B 模型 CPU 推理慢、不适合每条长政策解读；云端免费方案更稳。
- **批量重解读**：设置弹窗「批量重解读历史政策」后台对规则解读条目重新跑一遍解读（默认 50 条）；开启大模型后可由大模型对历史条目补做解读。按钮实时显示 `已完成 x/y`，完成后汇总成功/失败条数，单条失败不中断整批。
- **管理鉴权与站点配置**：保存配置、手动抓取、批量重解读、曝光抓取等写操作须先通过管理密码验证；首次默认密码 `admin123`（PBKDF2-SHA256 加盐哈希存储，不落明文），登录后会话 12 小时有效，可在设置弹窗内修改密码（新密码至少 6 位，需校验原密码与两次确认一致）。设置弹窗可配置：站点机构名称（注入大模型解读语境）、新增标记窗口天数、政策起始日期、列表抓取页数，以及定时频率/时刻、大模型开关/接口地址/API Key/模型；读取设置不鉴权（API Key 仅回显是否已配置，不回传密钥本体），写接口校验 `X-Admin-Token`，令牌失效或过期自动退回登录视图，未登录点抓取/重解读会先引导登录。

## 五、启动

- 双击 `start.bat`，或 PowerShell 执行 `./start.ps1`；服务在 http://localhost:8080 。
- 首次启动自动安装依赖；页面点「立即抓取」可手动跑一轮，之后按设定每日 / 每周自动抓取。

## 六、定时任务

- 默认每日 06:00 抓取；可在网页设置改为每周某时刻。调度基于进程内 APScheduler，
  服务运行期间生效；服务重启后自动按设置恢复。
- 命令行补抓：`python backend/crawl_once.py`。

### 抓取通道稳定性加固

- **HTTP 重试退避**：`config.REQUEST_RETRIES`（默认 3 次）对连接错误、超时、429/5xx 按指数退避 `RETRY_BACKOFF * 2**(n-1)` 重试；连接 10s / 读取 25s 超时分离，避免单次慢响应拖垮整轮。
- **分层容错**：单个栏目 / 分页失败只记入日志并跳过，不影响其他源；单条详情失败保留空条目待下轮补抓，不中断整源；列表 403/404 空分页静默跳过，不误报异常。
- **防并发重入**：模块级线程锁阻止手动触发与定时任务重叠抓取；重复触发返回 `skipped=running`。
- **SQLite 写锁等待**：抓取后台线程与 API 请求线程可能并发写库，连接设置 `timeout=5.0` 与 `PRAGMA busy_timeout=5000`，写锁竞争时最多等待 5 秒再返回，避免直接抛 `database is locked`。
- **编码与正文容器**：先读 meta charset，再 `apparent_encoding` 探测，`utf-8` 兜底；详情容器按站点多选择器兜底；详情请求携带来源站 Referer 提升通过率。
- 运行统计与失败明细落到 `crawl_log`（消息区分「成功：新增/更新/详情失败 k；列表页异常：…」），前端日志弹窗可查。

## 七、页面功能与交互

- 顶部模块导航 Tab 切换「政策解读 / 政策问答 / 医保曝光台」三视图，政策与曝光 Tab 带条目计数徽标；政策视图与曝光视图各自独立筛选与分页。
- 统计卡展示政策总数与三级分布，卡片本身可点击作为层级快捷筛选；层级标签与统计卡双向联动（选中层级高亮、其余淡化），标签与栏目均为可点击胶囊并带条目计数。
- 政策列表支持层级 / 栏目 / 常用主题快捷标签 / 关键词（标题、正文、文号）/ 日期或相关度排序筛选与分页；排序同为可点击标签。所有层级、栏目、主题标签与曝光类型 / 层级 / 机构类型均由后端按真实条目数统计后动态生成，标签上显示条目计数，0 条的选项自动隐藏（例如曝光台无国家层级通报时不显示国家入口）；市级条目另标注具体区县医保局来源。点主题标签按标签过滤，筛选区回显当前标签胶囊、可点 ✕ 清除；一键「重置筛选」清空全部条件，无结果时亦可清除筛选；长列表悬浮回顶部按钮；政策时间范围标注为 2024 年至今。点击层级 / 栏目 / 主题 / 排序 / 分页 / 统计卡 / Tab 后，页面自动平滑定位到对应结果模块（关键词输入保持焦点不打断）；命中卡片在筛选激活时以主题底色与边框高亮，被选中的层级 / 栏目 / 主题徽章同步以渐变突出，清除筛选后恢复默认样式。点击卡片右侧抽屉查看 AI 解读、要点、适用对象与原文，支持 ✕ 按钮、遮罩、Esc 关闭。抽屉 AI 解读为主卡：渐变玻璃头 + 解读类型角标，相关度以彩色仪表条 + 分数 + 分级文案（高度相关 / 一般相关 / 参考性）呈现，要点为带序号与左色条的立体条目，标签与适用对象分组小卡；另设核心要素键值网格、基层落地动作（绿色对勾条目）、待遇/支付标准（蓝条条目）、合规风险红线（暖红警示条目）分区；头部徽章标注政策类型、效力状态与整体影响分级；文号缺失时标注“留空待核验”，并列出原文关键数据；蓝底上位依据条、粉底市级/经办影响条，以及基层影响矩阵表（维度名 + 分级标签 + 进度条 + 判断说明，未涉及置灰标注“该维度未提及”），无内容分区自动隐藏。
- 曝光视图保留类型（案例/退出）、层级、机构类型筛选与关键词检索；退出机构区分主动 / 被动，违规案例不归类退出方式。
- **政策问答助手**：自然语言输入问题（或点常见问题快捷胶囊），后端 `/api/ask` 先按标题 / 标签 / 摘要关键词打分检索强相关政策（标题或标签命中 + 最低分门槛，排除公务员遴选 / 面试等非医保事务；无强相关时直接空态提示）；启用大模型时由 GLM-4-Flash 基于检索到的政策材料生成通俗结论、可执行要点与适用提醒，并列出可点击溯源的政策依据（点击打开政策抽屉）；大模型未启用或调用失败时回退规则摘要。回答气泡为立体卡片，标注「大模型问答 / 规则检索」。
- 列表顶部结果计数条显示「共 N 条政策」，并以可点 ✕ 胶囊回显当前层级 / 栏目 / 主题 / 关键词，点 ✕ 单项清除；关键词命中在标题、摘要、文号以暖黄底深字标记；政策卡片左侧色条按层级上色（国家蓝 / 云南青 / 玉溪琥珀），摘要两行截断、间距行距收紧；全局内容限宽 1180px 居中，筛选区为玻璃面板分组，统计卡图标与数字并排紧凑。
- 抓取日志以表格模态展示（时间 / 来源 / 发现 / 新增 / 状态 / 说明与耗时），不再使用浏览器弹窗。

## 八、静态发布（GitHub Pages，零服务器成本）

站点已改造为**纯静态前端**：`frontend/` 内页面直接读取 `frontend/data/*.json` 渲染，公网访问不依赖后端进程、数据库或常驻服务；`backend/` 仅作为抓取、规则解读与数据导出的工具，由定时任务调用。

- **本地预览静态站**：进入 `frontend/` 目录执行 `python -m http.server 8090`，浏览器打开 `http://127.0.0.1:8090/`。
- **本地一键重抓并导出快照**：进入 `backend/` 目录执行 `python run_pipeline.py`（初始化库 → 抓取政策与曝光 → 规则解读 → 导出 `frontend/data/*.json`）。
- **定时更新**：`.github/workflows/update-pages.yml` 每日（北京时间 08:00，可手动触发）在 GitHub Runner 上重跑流水线，回提交更新后的 `frontend/data` 快照，并通过 GitHub Actions 部署 `frontend/` 到 Pages。
- **本机改动同步到仓库**：在项目根目录执行 `.\sync-github.ps1 "提交说明"`（凭据取自本机 Git 凭据管理器，脚本不保存令牌）。脚本经 GitHub REST Git Data API 上传已跟踪源码；`frontend/data`、`frontend/assets`、数据库与日志仍由忽略规则排除，数据快照由 Runner 抓取后回提交。
- **大模型（可选）**：Runner 默认 `LLM_ENABLED=0`，走规则解读；如需大模型解读，在仓库 Settings → Secrets 配置 `LLM_API_KEY`（及可选 `LLM_ENABLED / LLM_BASE_URL / LLM_MODEL`），未配置或调用失败时自动回退规则解读。
- **不入库内容**：`backend/data/*.db*`（含口令哈希与业务数据）、运行日志、`__pycache__`、本地备选 LOGO 均已在 `.gitignore` 排除；仓库只提交前端壳、源码与 Runner 回提交的数据快照。
